# KarenBot 1.0.1-alpha.1

发布日期：2026-11-07

版本号：`1.0.1-alpha.1`；tag：`v1.0.1-alpha.1`

这是 `v1.0.1-alpha` 的增量版本，重点是人格工作模式下的工具档位热切换和设置页
可用性修正；不包含数据库或配置格式变更。

## 新增

- **工作模式工具档位热切换**：人格进入「工作」状态时自动把主工具档位切到 `agent`，
  退出工作后恢复配置中的原档位。切换只替换内存中的 `ToolRegistry`，不修改
  `config.yaml`，也不需要重启 Runtime。
- `work` 工具结果和任务上下文会告诉模型档位差异：哪些工具直接可用、其余工具
  如何用 `tool_search select=[...]` 加载，以及未加载调用返回 `need_tool_search`
  不是任务失败。配置本来就是 `agent` 时不重复切换。
- 同一 assistant 消息里先调用 `work`、再调用旧档位工具时保留一轮宽限 Registry，
  避免切换瞬间按新 schema 拒绝旧工具调用。
- 设置 →「软件行为」提供「工具 schema 档位」，并补充四个选项的详细说明，包含
  `routed` 与 `agent` 的机制、优缺点和适用场景。

## 变更

- 容器页 Agent 模式卡片的设置引导改为准确的「设置 → 软件行为 → 工具 schema 档位」。
- 设置页的重启提示和保存 toast 明确说明需要重启的是 **Runtime（后端）**，不需要
  重启或刷新前端。
- 设置项说明现在会随枚举选择动态更新，切换档位时可直接看到对应解释。

## 修复

- 动态工具执行器每次调用都解析当前 Registry；工作模式切换后的下一轮 schema 刷新
  会清理宽限状态，避免旧档位工具长期绕过 `need_tool_search`。
- 修复简化 Pipeline 测试替身缺少 `_dynamic_tool_executor` 时的兼容性回退。
- 修复编码 Agent 的 Windows 兼容性：host 后端可读取 CRLF 文件、对 CRLF 文本应用
  补丁并保留原换行，命令执行会查找 Git Bash；容器 helper 改用跨平台路径校验并
  强制 UTF-8 stdout。Windows CI 的 7 个失败用例随之修复。

## 验证

- 全量测试：**2798 passed in 455.87s**（`KAREN_DISABLE_TREND_RESEARCH=1`
  `KAREN_DISABLE_DEPENDENCY_CHECK=1`，排除依赖外部服务的 `test_kv_cache_real.py`）。
- 最终相关聚焦测试：**275 passed**；Ruff 和 `git diff --check` 通过；设置页/容器页
  JS 构建语法检查通过。
- `karenbot.service` 已重启并加载本版本，WebUI 返回 HTTP 200。

## 升级说明

- 手动修改「工具 schema 档位」仍然需要重启 Runtime（后端）才生效；工作模式的
  自动切换不需要。
- 前端静态资源有更新，升级后刷新一次 WebUI 页面即可看到新的设置说明和提示文字。
