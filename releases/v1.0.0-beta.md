# KarenBot 1.0.0-beta

这是 KarenBot 的首个 1.0 beta。自 `snapshot-20261030` 以来，人格图库、群聊接收控制、
存储/数据管理、知识/黑话、容器和管理界面都做了较大更新。

## 人格与聊天

- **多图角色形象**：人格页支持多选上传、逐张删除并指定预览图；图库和
  `manifest.json` 保存在 `personas/<name>/appearance/`。旧版单图 `image.*` 继续兼容。
- **角色形象可读可发**：`list_knowledge_notes` 会返回每张图的
  `persona-image:<当前人格>:<图片ID>` 引用；模型可以用 `describe_image` 查看，也可以
  把引用填入 `send_private_messages` / `send_group_message` 的 `image` 字段直接发送。
  LLM 仍没有修改或删除图库的接口，也不能读取其他人格的形象。
- **聊天选择**：新增 `chat_selection` 工具。模型可以临时暂停普通群聊接收，或只接收
  指定群；所有群的 @ 消息仍会送达，私聊完全不受影响，到时自动恢复。被过滤的普通群
  消息不会进入历史/事件流。
- **工作状态**：新增 `work` 工具和 `working` 状态，适合模型准备长时间处理容器任务。
  工作期间暂存群聊 @ 和私聊，普通群消息只记录；退出工作状态后统一交回模型。单次
  上限由设置 →「人格与生理」控制。
- **黑名单 / 白名单合并**：左侧「黑白名单」一页保存两套名单，pipeline 热更新，黑名单
  仍然优先。
- **可直接查看提示词**：直接写提示词保存时使用三引号 Python 字面量，源码预览保留
  实际换行，不再显示成大量 `\n`。已有提示词文件不会被自动改写。

## 知识与黑话

- 黑话管理页支持全文搜索；AI 提交与同群已有词条同名的申请会自动拒绝并留下可见记录，
  不会覆盖原词条。
- 同群黑话跨人格共享；知识条目支持逐条只读共享。
- 知识/黑话仍按需查询，不自动注入每轮上下文。

## 视觉、媒体与容器

- 主模型原生图片输入可用时，`describe_image` 会复用主聊天模型，不再要求额外配置
  独立视觉 provider。独立视觉开启时仍优先使用独立服务。
- 完整 GIF 和完整视频输入、QQ 原生表情名称映射、待注入媒体投影修复继续保留。
- 容器页新增只读 `/workspace` 文件管理器：目录导航、筛选、文本预览；符号链接不跟随，
  二进制文件只显示元数据。
- 保留受控 Docker 容器、B/C 存储、镜像加速、自动拉取和 Windows VHDX 初始化脚本。

## WebUI 与数据安全

- 「存储与缓存」和「数据管理」合并为「存储与数据」页：缓存盘点/清理、上下文预算、
  人格运行数据清理、本地完全卸载和管理任务集中在一页。旧 `#data_admin` 深链自动跳转。
- 危险操作继续使用预览 → 确认短语/勾选 → 后台任务；完全卸载由独立 stdlib-only
  助手在后端退出后执行，并保留审计记录。
- 侧栏可折叠为纯图标；模型配置集中在「模型管理」。

## 模型与依赖

- 中转站可选择上游模型厂商，自动套用 Gemini/Claude/OpenAI 等能力表。
- 启动时检查基础依赖，缺失时优先用 uv/pip editable 安装。
- 兼容旧 `debata` 命令、环境变量、数据目录和旧 cursor 密钥。

## 升级说明

- 版本号：`1.0.0-beta`；tag：`v1.0.0-beta`。
- 没有数据迁移，兼容声明保持 `data_contract_epoch=0`。
- 旧版角色形象 `appearance/image.*` 仍可读取；下次修改图库时会写入 manifest。
- 已有 `persona_prompt.py` 不会被自动改写。
- 当前数据目录仍兼容旧 `Debata_Agent` 路径；自动迁移命令尚未实装。

## 已知限制

- `chat_selection` 和「工作」暂存队列是 Runtime 内存状态；重启后恢复默认接收，
  重启期间未释放的暂存消息不会自动补发（原始 QQ 事件仍保留）。
- 容器文件管理器只读，不支持上传/下载/编辑；需要镜像内含 `python3`。
- 自动完全卸载支持 Linux 非 systemd 托管模式；systemd/Windows/macOS 显示手动步骤。
- Docker Hub 直连不可用时需配置镜像加速；C 存储变更大小需要采用实际大小或重建迁移。
