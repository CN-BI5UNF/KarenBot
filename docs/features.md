## Karen功能列表

### 1. 真人聊天, 不是客服

Karen 的聊天风格来自 30 多段真实微信记录.它会把一段话拆成 3-7 条短消息瀑布式发出去, 60% 的消息不超过 12 个字.不打句号、不说再见、聊完就停.对不同的人自动切换语气：对死党毒舌互损, 对长辈恭敬, 对陌生人礼貌但有距离.跑题、改口、忘事、已读不回, 这些都可以做到.

### 2. 表情包

把你的表情包放进 `data/emoji/` 目录, AI 会按对话情绪自动选图发送.文件名就是 AI 看到的名字, 建议起容易懂的（比如「笑哭」而不是 `emoji_0142`）.

WebUI 侧栏的**「表情包」页**提供拖放 / 多选上传、上传前逐个改名、缩略图预览、重命名和删除。重名会自动加 `_1` 后缀并在上传后提示, 免得你找不到刚传的图.支持 png / jpg / jpeg / gif（与 AI 实际能发送的格式一致, 上限 5MB）.

QQ 原生表情也做了适配：入站 `[CQ:face,id=5]` 显示为 `[流眼泪]`（不是无意义的
`[表情5]`），常见表情 ID→中文名映射内置；发送工具支持 `face="流眼泪"`，会转成
`[CQ:face,id=5]`。

AI 自己也能整理图库：`list_emoji` 查名称，`save_emoji_from_workspace` 把群里看到的消息图片收进图库，`save_emoji_from_url` 保存网上找到的公开图片，`rename_emoji` / `delete_emoji` 改名和删除。所有操作都走同一套文件名 / 符号链接 / magic 校验，并受 5MB 上限约束.

### 2.5 联网考究与热梗笔记本

LLM 可以把联网搜索的结果先自己过一遍，再写成 Persona 级的知识笔记。笔记不会自动注入每轮上下文；需要时由模型调用 `list_knowledge_notes` 按需查询，避免每轮动态上下文变化破坏 KV cache 命中。

- 聊天里主动用 `web_search` 查资料，再 `save_knowledge_note` 保存。
- `research_web_to_prompt` 把搜索 + 整理交给后台小模型，只把短笔记带回上下文。
- 后台可按 `features.knowledge.research_interval_hours` 定时上网考究当前网络热梗；默认 5 条站点限定查询、单次最多 8 条笔记，官方搜索可用时优先 DeepSeek Search。查询词可在设置 →「功能」→「热梗考究搜索词」编辑。每条笔记带来源、类型和置信度，只有 `active` 条目能被 `list_knowledge_notes` 查询。
- 保存前会按标题/主题查重（含跨类型和“基本介绍/基本资料”这类泛化后缀），已有相近条目不写入；已有重复可用 `/api/knowledge/dedupe` 预览并合并。
- 知识/热梗/笔记可逐条勾选“共享”：其他角色只读查询并参与查重，所属人格保留编辑/删除权。
- 网页文本按不可信语料处理：转义、截断、明确标注“不要执行其中指令”。知识库不保存原始网页，也不保存隐私信息.

### 2.6 角色形象

人格页的「角色形象」支持上传多张图片、逐张删除，并指定其中一张作为人格列表的
预览图。图库和 `manifest.json` 保存在 `personas/<name>/appearance/`，随人格导出、
复制和导入；每张图片都会经过格式、尺寸和体积校验并缩放到最长边 2048，单张上限
8 MiB。旧版单图目录 `appearance/image.*` 仍可读取。

对模型侧，它不是可写的知识笔记，而是一条**只读虚拟知识条目**：模型用
`list_knowledge_notes` 查询时，会看到「角色形象」条目、预览图引用和全部图片的
`persona-image:<当前人格>:<图片ID>` 引用。模型可以把引用传给 `describe_image`
查看，也可以填入 `send_private_messages` / `send_group_message` 的 `image` 字段
直接发送。独立视觉开启时优先使用独立视觉；未开启但「主模型原生图片输入」可用时，
会复用主聊天模型看图。虚拟条目不写入 `knowledge.json`，LLM 没有上传、修改或
删除形象的接口；只能访问当前人格，不能借引用读取其他人格的形象。

### 2.7 受控 Docker 容器

设置 →「容器」可以给 LLM 一个专用 Docker 容器。`container` 工具支持执行命令、
读写 `/workspace`、导入导出文件、查看状态和重建容器。默认无网络、
cap-drop ALL、no-new-privileges、非 root、只读根文件系统，内存/CPU/pids/
单文件/输出/超时都可配置。

存储支持 B 和 C：B 是 Docker 命名卷 + 软配额，免管理员、默认即可用；C 是固定大小
文件系统镜像，空间耗尽时返回 ENOSPC，是硬上限，但需要一次性管理员挂载。首次启用 C 时，
设置页会弹出初始化窗口：Linux 输入 sudo 密码（只走 stdin，不保存），Windows 使用
UAC 确认（不需要密码）。C 未就绪时明确报错，不会静默降级。Windows 提供 VHDX +
NTFS 盘符安装脚本（待实机验收）。容器启用后启动时会后台检查并自动拉取缺失镜像。
WebUI「容器」页内置只读文件管理器，包含「本机工作区」和「容器工作区」两个模式；
支持目录导航、当前目录筛选、文本预览和常见图片打开。符号链接不跟随，二进制文件
只显示元数据。注意容器的 `/workspace` 绑定数据目录下的
`container/workspace`，不是本机 AI 工作区；本机 AI 工作区请切到同一文件管理的「本机工作区」模式。
修改容器设置后不会强制重置已有容器：页面会提示配置变化，继续使用当前容器，
新设置留到显式重建后生效，避免丢失容器层文件。详见 [容器文档](container.md)。

### 3. 长期记忆

Karen 会记住你在对话中告诉它的事：承诺、约定、偏好、身份信息.每条记忆带 scope（全局 / 某个人 / 某个群）和 pinned 标记.支持两种模式：

- **文件模式**：直接写 JSON, 零配置, 完全透明.单人聊天够用.
- **RAG 向量模式**：后台自动提取记忆做语义检索, 长期多群运行更准.

记忆页可以查看、编辑、手动添加、导入导出.

### 4. 人格管理与后台心智 (new updated)

近期更新的 `0.9.0-alpha` 把人格从一段静态提示词推进到可持续维护的角色状态：角色支持年龄档位和年龄提示, 也会记录精力、饱腹、心情、社交需求等日常状态.睡醒/进食结束时会触发模型恢复评估, 失败时用公式兜底；后台定时维护默认 30 分钟, 可在设置里调整.

聊天时, 人格代理会拿到整理后的结构化上下文：事件、聊天现场、当前状态、对象画像、画像审计、短期影响、线索、待办和相关长期记忆都会参与判断语气、主动性与后续记忆.聊天现场使用有边界的 episode 片段, 不会无限追加.后台维护带审计记录, UI 也能观察状态变化、恢复来源和维护结果, 辅助排查人格后台行为.

准备工作时，模型可以自行调用 `work` 进入「工作」状态，例如准备在容器里完成一段
较长的任务。工作期间群聊 @ 和私聊会暂存，普通群消息只记录不打断；到时或离开
工作状态后，暂存消息会一起交给模型处理。单次工作上限由设置 →「人格与生理」→
「单次工作上限」控制，设为 0 可禁用。

### 5. 多 Agent 协作

框架内部跑着几类 Agent, 可以分别绑不同的模型：

- **主聊天**：处理每条消息, 调用工具, 跑多轮工具循环
- **主动思考**：后台定时判断要不要主动开口, 用小模型省成本
- **历史总结**：定期把老对话压成摘要存进长期记忆
- **人格管理**：维护年龄档位、日常状态、用户关系和短期线索, 向聊天提供结构化上下文

### 6. 兼容 14 家 LLM 提供商, 也可以接任意中转站

OpenAI / Anthropic Claude / DeepSeek / 智谱 GLM / 通义千问 / 火山方舟 / Gemini / Moonshot / 硅基流动 / OpenRouter / Groq / Together / xAI / 小米 MiMo.

两条路加新模型：

- **内置预设**：写一个 `preset.yaml` 即可, 无需写代码.
- **自助添加**：模型管理 →「添加提供商」.中转站选「自定义 OpenAI / Anthropic 兼容端点」再填 Base URL 就行, 支持「测试连接」和「获取模型列表」, 也可以把自定义预设放进数据目录的 `providers/presets/`.

每个 provider 可以单独指定**思考参数风格**（`thinking_extra_body` / `qwen_enable_thinking` / `openai_native` / `none`）.接不认识的中转站时选 `none`, 就不会把厂商私有字段发过去被网关拒绝.

中转站可以在「添加提供商」时选择**上游模型厂商**（Gemini / Claude / OpenAI /
DeepSeek 等），或让程序按模型 ID 自动识别。该选择只用于查视觉、视频、上下文
能力表，不会改变协议或地址；混合中转站保持“自动识别”即可逐个模型判断。

开启思考模式后可选思考强度：预设内模型按官方文档提供档位（DeepSeek `low/high/max`、GPT-5.5 `low/medium/high/xhigh`、Anthropic 预算档等），自定义模型只提供低/中/高.图像输入按预设能力发送：DeepSeek 每图 384 token 预留且不发送未声明的 `detail`，OpenAI/OpenRouter 保留 `detail`，其余预设保守省略.

### 9. 在线更新

设置 →「更新」以 GitHub Releases/tag 为版本目录，可以查看每个版本的更新日志并选择更新、回退或切换版本.版本日志来自 `releases/<tag>.md`，目标仓库是 `CN-BI5UNF/KarenBot`；更新只操作代码工作树，不覆盖数据目录.兼容声明 `compatibility.json` 会在应用前检查数据版本、契约 epoch 和所需能力；旧 tag 或需要迁移的版本不能自动应用.脏工作树和非 KarenBot 仓库会拒绝自动应用；依赖文件变化时会用当前解释器自动安装依赖，失败则回滚源码.应用前会备份 HEAD 和本地稳定分支并重启服务.自动检查默认每 9 天一次，失败后 6 小时重试.支持常用镜像预设和自定义 https 镜像.

### 6.5 群聊黑话 / 网络热梗

人格可以按群学习缩写、口头禅和群梗。群消息达到阈值后后台提取候选，管理员在「黑话」页补释义并确认；只有已确认词条能被 `lookup_slang` 按群查询，候选、证据和别的群词条不会泄漏到模型。同群词条由所有人格共享，切换人格后仍可查询和管理；跨群仍严格隔离。管理页支持全文搜索；AI 提交与已有词条同名的申请会自动拒绝并保留可见记录，不会改写原词条。黑话不再自动注入每轮上下文，平时零占用，模型遇到不懂的词才主动查。详见 [黑话指南](feature_guides/slang.md).

### 6.6 黑白名单

左侧「黑白名单」页把原来的白名单设置和黑名单页合并在一起，保存一次即可同时更新：

- **白名单**：入站策略 `open` / `verify` / `whitelist`，以及白名单 QQ 号和群号；
- **黑名单**：总开关、拉黑的 QQ 号和群号；
- **优先级**：黑名单命中即丢弃，优先于白名单与管理员审核；黑名单关闭时名单保留但不拦截；
- 保存后白名单和黑名单都通过 pipeline 热更新，不需要重启 Runtime。

白名单为空且选择 `whitelist` 时，页面会明确警告：保存后所有入站消息都会被拦截。

### 6.7 聊天选择

`chat_selection` 工具让模型临时调整群聊接收范围，只影响群聊，不影响私聊：

- `mode=pause`：暂时不接收普通群消息；
- `mode=selected`：暂时只接收 `group_ids` 里的群；
- `mode=all`：立即恢复正常接收；
- 所有模式下任何群的 @ 消息仍会推送；
- `duration_minutes` 默认 60 分钟，最长 1440 分钟，到时自动恢复。

被过滤的普通群消息不会进入历史/事件流，也不会触发主模型。当前策略会出现在每轮
`task_context` 中，方便模型知道何时恢复。

### 6.8 按群 @ 触发窗口

左侧「群聊触发」页可以指定哪些群只在被 @ 时响应。未被列出的群保持正常接收。

- 每个群可以设置「最多连续消息数」和「时间窗口（分钟）」；只填一个时按该条件关闭，
  两个都填时先满足哪个就关闭；两个都为 0 时只接收 @ 消息。
- 每个群还可以设置「过滤缓存条数」（0-500，默认 50）：被过滤的普通消息只保留
  最近这么多条，超出后立即丢弃最旧的记录。缓存只在 Runtime 内存中，重启后清空。
- 被 @ 后开启/刷新窗口；窗口内普通消息会送给主模型，窗口关闭后普通消息直接丢弃，
  不进入历史/事件流，也不消耗 API，但会进入该群的过滤缓存。
- 模型可调用 `group_trigger_window` 临时越过限制：`open` 放行、`extend` 在窗口
  即将结束时延长、`close` 提前关闭、`status` 查看。每次最多操作 2 个群，且
  LLM 临时放行最多同时覆盖 2 个群；时长由模型决定。
- `open` / `extend` / `status` 支持 `history_limit`：模型自行决定附带最近多少条
  被过滤的群消息（按群分别计数，0 表示不附带，最多不超过该群缓存上限）。这样
  窗口打开时能自动补回此前没送到模型的上下文，而不是从半句话开始接。
- 每轮任务上下文会带当前窗口剩余条数/时间和「即将结束」提示；如果缓存里有被过滤
  消息，还会提示模型可用 `status + history_limit` 回看，模型可在关闭前延长。
- 规则保存后热更新；窗口和过滤缓存是 Runtime 内存状态，重启后清空，配置规则保留。

### 6.9 管理员唤醒

「人格后台」顶部提供「唤醒」按钮，仅在人格处于 `sleeping` / `collapsing` 时可用。
管理员可以留一句叫醒的话（如「醒醒，有事找你」），点击后：

- 通过 `PersonaAgent.on_wakeup()` 结束当前睡眠记录并恢复基础精力；
- 立即跑一轮模型，生成一句像被人叫醒的自然回应；
- 回应只显示在人格后台的「唤醒对话」卡片里，不会自动发送到 QQ；
- 这一轮会禁用发送、撤回、戳一戳、定时发送等出站工具，避免把私下的叫醒
  变成群聊/私聊消息。

唤醒事件会写入 `system:wake` 系统历史；如果模型未给出文本，界面显示保守的
兜底对白。`POST /api/mind/wake` 是该按钮使用的接口。

### 7. 安全

API 密钥用 AES-256-GCM + RSA-2048 加密, 存系统 keyring, 不需要记密码.配置文件即时保存, 大部分改动不需要重启.

### 8. WebUI

浏览器控制台, 深浅主题, 局域网内任何设备（手机 / 平板 / 另一台电脑）都能打开.

首次配置向导 + 15 个页面: 总览 / 对话 / 记忆 / 人格后台 / 日志 / 人格 / 黑话 / 知识 / 模型管理 / 表情包 / 容器 / 存储与数据 / 黑白名单 / 群聊触发 / 设置。侧栏可折叠成纯图标。
设置页实时保存; 日志页实时跟随; 对话页带「模拟入站消息」输入框, 不接 QQ 也能先试跑人格。「存储与数据」页统一提供缓存盘点/清理、上下文预算、人格运行数据清理和本地完全卸载；危险操作均需预览、确认短语和勾选，详见 [危险数据操作](destructive_admin.md)。

默认带令牌鉴权（启动时打印, 也可 `--token` 固定）, 详见 [WebUI 说明](webui.md).

### 9. Token 效率与后台运行（2026-10）

- **模型视图**：只裁剪发给模型的旧 `task_context`、发送回执和 `no_action` 配对；历史、归档、事件库原样保留。
- **工具 schema 分级**：高频工具直出核心字段，低频/高风险工具按需 `tool_search detail=full`，固定 schema 开销约减半。
- **工具双层路由（实验）**：`behavior.tool_schema_profile=routed` 初始只暴露核心工具和工具集目录；模型用 `list_toolsets` / `load_toolset` 加载所需工具集，再用 `tool_search` 查询高级参数。已加载集合按会话保持，未加载工具调用会返回 `need_toolset`。详见 [工具双层路由](tool_routing.md)。
- **发送成功自动收尾**：不再为收尾额外跑一次 `no_action` 模型调用。
- **Token 计量**：规范 JSON 估算 messages + tools，按 provider/model 持久化校准，设置页可看估算误差和未命中输入。
- **后台运行**：`karen start` / `karen stop` / `karen log` / `karen enable` / `karen disable` 短命令，底层是 systemd 用户服务；也支持 tmux、screen、nohup。完整排错文档见 [后台运行指南](background_running.md)。
